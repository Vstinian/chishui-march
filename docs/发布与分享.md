# 发布与分享

当前游戏没有后端，构建出的 `dist/` 可以托管为静态网站。玩家只需要浏览器。开发者电脑关机后，托管网站仍可访问；本机 `localhost` 或 `127.0.0.1` 地址只能用于本地调试。

## 首次发布：GitHub Pages

1. 在 GitHub 打开 `Vstinian/chishui-march` 仓库。
2. 打开 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。需要仓库管理或维护权限。免费个人账户使用 Pages 时，仓库需要为公开仓库；私有仓库支持情况取决于 GitHub 套餐。
3. 提交本地需要发布的代码和 `.github/workflows/deploy.yml`，推送工作分支，创建 Pull Request 合入 `main`。本地改动只有保存还不会同步到 GitHub。
4. 在仓库 **Actions** 中打开 **Deploy game to GitHub Pages**。流程自动安装依赖、检查通关流程、构建并发布 `dist/`。
5. 流程成功后在 **Settings → Pages → Visit site** 获取正式地址；当前仓库默认地址预计为 `https://vstinian.github.io/chishui-march/`，以 GitHub 实际显示的地址为准。

如部署文件已经在 `main` 中，开启 Pages 后可在 Actions 中手动运行此流程，并选择 `main` 分支。工作分支不会通过该流程发布正式站点。

当前 Vite 使用 `base: './'`，构建资源通过相对路径加载，适用于仓库子目录。之后加入的背景、立绘、音频也使用 `assets/...` 相对路径，并随文件提交；不要填写本机 `D:\...` 路径。Linux 托管区分文件名大小写，配置与实际文件名须一致。

## 后续更新

在工作分支修改 → 本地检查 → 推送 → Pull Request 合入 `main` → 自动更新原网址。玩家无需重新安装；若浏览器仍显示旧页面，刷新页面后再看。

发布内容是 `dist/`，无需把 `node_modules/` 或 `dist/` 提交到仓库，也不用让玩家运行 npm。所有试玩进度保存在各自浏览器中，不会自动跨设备同步。

正式交付前，用手机流量和不同运营商网络实际打开链接，检查首次载入、图像、音频和通关流程。若目标评审网络访问效果不满足要求，可以把同一份 `dist/` 交给学校已有网站或国内静态托管服务部署，并保留 GitHub Pages 为备用。
